# Cloudflare Workers monorepo

pnpm workspace with turbo. `packages/workers-shared` is a shared library; each folder under `workers/` is one Cloudflare
Worker. The repo is **public**.

## Cloud sessions

- Use the **Node.js Dev** environment if it's available.
- Node.js and pnpm must match `devEngines` in the root `package.json` (Node 26.13.0, pnpm 12.16.1 at the time of
  writing). Check with `node --version` and `pnpm --version` before installing anything. An older pnpm fails
  `pnpm install --frozen-lockfile` with `ERR_PNPM_BROKEN_LOCKFILE`, because the lockfile has more than one document.
- If turbo tasks fail with `Exec format error (os error 8)` while the same script works when run directly, the `pnpm`
  that turbo starts isn't a real executable yet. Fix the pnpm install rather than working around turbo.
- Install with `pnpm install --frozen-lockfile`. Don't add exclusions to `minimumReleaseAgeExclude` in
  `pnpm-workspace.yaml`; pick dependency versions old enough to pass the release-age check instead.

## Commands

Run from the repo root.

| Command                             | What it does                                                                                                   |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `pnpm build`                        | `wrangler types`, then `check`, then `wrangler deploy --dry-run` for each worker and tsdown for workers-shared |
| `pnpm check`                        | `tsc --noEmit` per package (and `-p tests` where a package has tests)                                          |
| `pnpm test`                         | Vitest in each package that has a `test` script                                                                |
| `pnpm lint`                         | Builds first, then oxlint with type-aware rules                                                                |
| `pnpm lint:ci`                      | oxlint only; needs a build already done                                                                        |
| `pnpm format` / `pnpm format:check` | oxfmt                                                                                                          |

Filter to one package with `pnpm -F <name> <script>`, e.g. `pnpm -F discord test`.

`.github/workflows/pr.yml` runs `pnpm build`, `pnpm test`, `pnpm format:check` and `pnpm lint:ci`. Run all four
before pushing, and run `pnpm format` before each commit.

## Pull requests

- `pr.yml` skips draft PRs, so open PRs ready for review, or CI never runs.
- PRs merge through a merge queue. Never merge or enqueue a PR yourself.
- Cloudflare Workers Builds reports a check per affected worker. On a branch these are **preview** builds, which use the
  `previews` block of `wrangler.jsonc`.

## Cloudflare account and deploys

- Don't run anything against the Cloudflare account: no `wrangler deploy`, `wrangler secret put`, remote D1 queries or
  migrations, or queue sends. `wrangler types`, `wrangler dev` and `wrangler deploy --dry-run` are fine.
- When a change needs something done on the account or in Discord, write the exact command in the PR description for
  the maintainer to run.
- **D1 migrations apply automatically** in the Workers Builds scripts, for both preview and production builds. Don't
  ask for migrations to be applied by hand before a merge or deploy. Generate them with `pnpm -F discord db:generate`
  (drizzle-kit) after changing `workers/discord/src/db/schema.ts`.
- `secrets.required` in a worker's `wrangler.jsonc` makes its production build fail until each secret exists. Previews
  don't inherit it.
- Bindings don't carry over from the top level of `wrangler.jsonc` into `previews`; previews get only what the
  `previews` block lists. Leave a binding out of `previews` to keep previews away from a production resource.
- `worker-configuration.d.ts` is generated by `pnpm -F <worker> types` and committed. Regenerate it after any change to
  `wrangler.jsonc`.

## Public repo

No real email addresses, Discord IDs, names, guild IDs, tokens or rules anywhere: code, tests, config or migrations.
Use `example.com` and `example.co.uk` addresses and placeholder snowflakes (e.g. `100000000000000001`) in tests. Real
values live in secrets or D1 rows.

## Workers

- **discord**: queue consumer for `discord-message-queue`. It posts, edits and deletes messages as a bot or through a
  webhook, and syncs slash commands with Discord. Bot tokens and webhook tokens live in its D1 (drizzle), never in
  queue bodies. Its Discord API is mocked in `tests/discord.ts`; `pnpm -F discord test:live` hits real Discord and needs
  environment variables, so don't run it.
- **bona-fide-bot**: Discord bot. It answers interactions over HTTP with Hono, keeps Gateway shards running in Durable
  Objects (reconciled by a 10-minute cron), and calls mail-screener over a service binding.
- **mail-screener**: Email Worker that screens mail for one domain against sender rules in a Durable Object, and posts
  review cards through the discord worker. Other workers call its `ScreenerService` entrypoint.
- **webhooks**: receives GitHub webhooks and posts them to Discord. `src/types/github.ts` is generated
  (`pnpm -F webhooks types:openapi`) and ignored by lint.
- **workers-bachman-dev**: static assets for a custom domain.

Workers talk to each other through queue bodies and RPC contracts in `@bachman-dev/workers-shared`
(`/cloudflare`, `/discord`, `/http`, `/screener`, `/util`). Never import from another worker's folder. Queue bodies
must stay backward compatible, since messages already queued keep their old shape. A new subpath needs an `exports`
entry in `packages/workers-shared/package.json` and an entry in `tsdown.config.ts`.

Slash commands are defined only in the worker that handles them, with `scope: "global" | "guild"`. That worker queues a
`sync-commands` body; the discord worker's `command_guilds` table says which guilds get each guild command.

## Code style

The oxlint config (`@bachman-dev/oxc-config`) is strict. Rules that come up most:

- JSDoc on every function, with `@param {Type} name - …` and `@returns {Type} …`.
- No type assertions (`as`), not even `as unknown as` in tests. Narrow with type guards, `in` checks or
  `Array.prototype.some`. In tests, call an API with bad input through a helper typed with `unknown` arguments
  (e.g. via `Reflect.apply`).
- Exports go at the end of a file (`export { a, b };`), except `export default`.
- Interfaces use property signatures (`name: (arg: T) => R`), not method signatures.
- No magic numbers: name them as constants.
- Comments start with a capital letter.
- `await` with try/catch, not `.then()` or `.catch()`. A `catch` binds the error and uses it.
- At most 4 function parameters, and identifiers of at least 3 characters.
- No `= undefined` initializers. Arrow functions returning an object use a block body.
- Awaiting in a loop needs `// oxlint-disable-next-line no-await-in-loop -- Must be in order`, or another reason.
- Vitest: `it.for` rather than `it.each`, `expect.hasAssertions()` at the start of each test, a message for every
  `toThrow`, and no `expect.objectContaining` (it's typed `any`). Read mock calls from `.mock.calls` instead.

Conventions:

- Log with `log(level, ...items)` from `@bachman-dev/workers-shared/util`, not `console` directly.
- Each worker's `src/types/cloudflare.ts` declares `interface Env extends Cloudflare.Env`, overriding generated binding
  types where they need to be more specific (typed queues, Durable Object classes, RPC contracts). Use
  `Omit<Cloudflare.Env, "NAME">` to change a binding's type or make it optional.
- Discord messages use Components V2. Any reply or post that echoes user text sets `allowed_mentions: { parse: [] }`,
  and shows untrusted text as inline code with backticks swapped for `ˋ`.
- Write US English in code, comments and docs.

## Tests

- Vitest and `@cloudflare/vitest-plugin` come from the repo root. Each package's `vitest.config.ts` runs the worker from
  its `wrangler.jsonc` with placeholder secrets in `miniflare.bindings`, and an `outboundService` that fails any network
  request.
- Each config aliases `discord-api-types/v10` to the CommonJS build resolved from workers-shared. Copy that alias into
  any new worker's config, or its enums come through undefined.
- A service binding to another worker needs a stand-in in `miniflare.serviceBindings`, or workerd won't start. Tests
  pass fakes through the `env` argument instead.
- `tests/tsconfig.json` in each package type-checks the tests; the package's `check` script runs it.
